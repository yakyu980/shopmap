# Home QA Agent Playbook

מטרת הסוכן: לבדוק את דף הבית, רשימת הקניות, הקשר האישי/קבוצתי והמעבר לניווט מנקודת מבט של לקוח אמיתי.

## מסלול בדיקה מחייב

1. לפתוח את האתר בגרסה חדשה ולוודא שבסרגל הראשי קיימים רק `דף בית` ו-`ניווט`.
2. בדף הבית לוודא שהכותרת, פרופיל/קבוצות, בחירת סניף, חיפוש, מועדפים ורשימת הקניות נגישים ב-RTL ובמובייל.
3. לחפש מוצר, להוסיף אותו, ולוודא שמופיעים הודעת הצלחה, מונה, כמות 1 וכפתור `עבור לניווט בסופר`.
4. לשנות כמות, לסמן כנקנה, להזיז ולהסיר; בכל פעולה לבדוק שהסכום והרשימה נשארים עקביים.
5. להיכנס למועדפים ולוודא שהרשימות `כללי`, `קיץ` ו`חורף` נפתחות בלי לאבד את הרשימה הראשית.
6. לפתוח פרופיל, לעבור בין `הרשימה שלי` לקבוצה, ולוודא שהכותרת, המוצרים והסניף מתחלפים. חזרה ל`הרשימה שלי` חייבת להחזיר נתונים אישיים בלבד.
7. בקבוצה לבדוק הצטרפות, רשימת חברים, הרשאות, הוספה ועדכון מוצר. לבצע רענון ולוודא שהנתונים נשארים מסונכרנים.
8. לעבור לניווט ולוודא שמוצגים מספר תחנות, זמן משוער, מוצרי התחנה, `חזרה לרשימה` ו`עבור לקופות`.

## כללי הצלחה

- אין ערבוב בין רשימה אישית, קבוצה או משתמש אחר.
- אין `NaN`, רשימה ריקה מטעה או פעולה שמדווחת כהצלחה לפני שהשרת אישר אותה.
- אין כפתורים כפולים/לחיצות מתחרות בזמן שמירה.
- שינוי רשימה בזמן שמסך הניווט פתוח מרענן את התחנות.
- שגיאות מסבירות מה נכשל ומציעות ניסיון חוזר.

## איך הסוכן נותן משוב אמיתי של לקוח

בכל תרחיש הסוכן מתעד לא רק תוצאה טכנית, אלא גם חוויית שימוש:

| שדה | מה לכתוב |
|---|---|
| פעולה | מה הלקוח ניסה לעשות |
| ציפייה | מה אדם סביר ציפה שיקרה |
| תוצאה | מה קרה בפועל |
| חיכוך | מה היה איטי, מבלבל, מוסתר או לא אמין |
| השפעה | האם הלקוח נתקע, טעה, איבד מידע או רק התעכב |
| חומרה | P0 חסימה, P1 בעיה מרכזית, P2 שיפור שימושיות |
| המלצה | שינוי ממוקד שמקטין את החיכוך |

הסוכן צריך לשאול את עצמו אחרי כל מסך: “אם זו הפעם הראשונה שלי באפליקציה, האם ברור לי מה הצעד הבא?”. הוא בודק גם מקרים לא מושלמים: רשת איטית, מוצר בלי מחיר, קבוצה ריקה, הרשאה חסרה, מוצר בלי תחנת ניווט ולחיצה כפולה. אין לדווח “עבר” רק מפני שהקוד לא זרק שגיאה; פעולה נחשבת מוצלחת רק אם היא ברורה, עקבית והנתונים נשארים נכונים אחרי רענון.

## תבנית דוח אנושית

`P1 — הוספת מוצר לקבוצה`

“ניסיתי להוסיף מוצר לרשימת הקבוצה. ציפיתי לראות אותו מיד עם אישור ברור. בפועל הופיע אישור לפני שהשמירה הסתיימה, ולכן כלקוח לא ידעתי אם אפשר לצאת מהמסך. זה מסוכן כי כשל רשת עלול להיראות כהצלחה. המלצה: להציג מצב שמירה, לנעול את הכפתור, ורק לאחר אישור שרת להציג הצלחה.”

## ממצאים שדורשים המשך טיפול

- מסך הניווט מאתחל מסלול פעם אחת ועלול לא להתעדכן כשמשנים את הרשימה.
- מעבר קבוצה מתוך הפרופיל אינו מכריח חזרה לדף הבית אם המשתמש נמצא בניווט.
- אין מצב טעינה מפורש לנתוני קבוצה.
- פעולות קבוצה חסרות נעילה/מניעת לחיצה כפולה.
- מחיר חסר עלול להוביל לחישוב `NaN`.
- רשימה עם פריטים ללא תחנת ניווט צריכה הודעה ברורה במקום מצב “הגעה לקופות”.
