# SuperNav AI — MVP

"ה-Waze של הסופר" — אפליקציית React/Vite שמדגימה את הליבה של הרעיון:
מפת סופר לוגית, רשימת קניות, וחישוב מסלול-קנייה אופטימלי בין המחלקות.

## היקף ה-MVP הזה

נבנה עם **נתוני-דוגמה סטטיים לסניף אחד** (`src/data/storeData.js`) — ללא
שרת, ללא AI אמיתי לזיהוי מוצרים בתמונה, ללא מאגר מחירים ארצי. אלה שכבות
עתידיות שדורשות תשתית שרת/ML נפרדת.

מה שכן ממומש ועובד:

- **מפת חנות** — רשת מחלקות לוגית (`🗺️ מפת חנות`).
- **קטלוג מוצרים + מיקום** — כל מוצר עם מחלקה/מדף/אזור (15 אזורים למדף,
  5×3, כמו בספֵּסיפיקציה).
- **רשימת קניות** — חיפוש מוצר, הוספה/הסרה, סה"כ מחיר.
- **מסלול אופטימלי** — אלגוריתם Nearest-Neighbor שממזער הליכה בין
  המחלקות שיש בהן מוצר ברשימה (`src/lib/route.js`), מהכניסה לקופות.
- **ניווט צעד-אחר-צעד** — תחנה נוכחית מודגשת על המפה, סימון מוצרים
  שנלקטו, מעבר לתחנה הבאה, מסך סיום בקופות.
- **אימות קהילתי (mock)** — כפתורי "נמצא"/"לא נמצא" לכל מוצר
  (`src/lib/verification.js`, `localStorage`); אחרי כמה דיווחי "לא נמצא"
  המוצר מסומן כ"ייתכן שעבר מקום".
- **היסטוריית מחירים (mock)** — גרף-עמודות דטרמיניסטי לכל מוצר
  (`src/lib/priceHistory.js`), עם מגמת עלייה/ירידה.
- **ניווט AR במצלמה (דמה)** — כפתור "📷 ניווט AR" בתוך הניווט פותח מסך
  מלא עם תמונת-מצלמה חיה (`getUserMedia`) וחץ-כיוון גדול (`src/lib/direction.js`)
  שמצביע לאן ללכת כדי להגיע למחלקה הבאה, לפי הגיאומטריה הלוגית של המפה —
  **לא זיהוי-מדפים/AR אמיתי**, רק חץ דמה לפי מיקום-המחלקה. אם אין הרשאת
  מצלמה/דפדפן לא תומך, המסך נופל בחזרה לרקע ניטרלי והחץ ממשיך לעבוד.
- **עדכון מיקום-משתמש** — ארבע דרכים משלימות (זמינות גם בניווט הרגיל
  וגם בתוך מסך ה-AR): **(1)** כפתור "📍 עדכן מיקום" לבחירה ידנית של
  המחלקה שבה אתה נמצא, **(2)** פרומפט יזום כל 90 שניות ששואל "איפה אתה
  נמצא עכשיו?" (`src/components/LocationCheckin.jsx`), **(3)** מד-צעדים
  ניסיוני (`src/lib/useStepCounter.js`, מבוסס `DeviceMotionEvent`) שנותן
  הערכת-מרחק גסה מאז העדכון האחרון ומרמז כשכדאי לעדכן מיקום — לא
  מפעיל ניתוב-מחדש בעצמו, **(4)** **GPS אמיתי (לא mock)**
  (`src/lib/useGeolocationWatch.js` + `src/lib/geoMatch.js`) — במסך
  "מפת חנות" בעריכה אפשר לכייל קואורדינטת-GPS אמיתית לכל מחלקה
  (עומדים בפועל ליד המחלקה ולוחצים "📍 קבע GPS למיקום הנוכחי"); בניווט,
  אם יש קליטת-GPS מדויקת (≤30מ') שתואמת (≤60מ') מחלקה מכוילת, המיקום
  מתעדכן **אוטומטית** בלי לשאול כלום — **והפרומפט היזום (2) מפסיק לרוץ
  כל עוד יש קליטה שמישה**, וחוזר לפעול ברגע שאין. GPS אמיתי כמעט תמיד
  לא עובד בתוך מבנה סגור (בד"כ רק ליד כניסה/חלונות/חוץ) — זה מתועד
  בממשק, לא מוסתר. דיווח-מיקום (מכל אחת מהדרכים 1/2/4) שאינו תואם
  לתחנה הצפויה מפעיל **ניתוב-מחדש** של יתרת המסלול
  (`reorderRemainingStops` ב-`src/lib/route.js`).
- **רשימת קניות קולית + חיפוש קולי** — מבוסס Web Speech API
  (`src/lib/useSpeechRecognition.js`, `he-IL`). כפתור "🎤 הוסף בקול"
  ברשימת-הקניות מקשיב למשפט חופשי ("אני צריך חלב, קפה וביצים"), מפרק
  אותו ליחידות-מוצר (`src/lib/voiceParse.js` — פונקציות טהורות, ללא
  תלות בדפדפן), ומנסה להתאים כל יחידה למוצר בקטלוג; מה שהותאם נוסף
  אוטומטית לרשימה, ומה שלא נמצא מוצג בבירור כ"לא נמצא במלאי". כפתור 🎤
  נוסף גם בתיבת-החיפוש הרגילה (`ProductSearch`) למילוי-קולי מהיר של
  שדה-החיפוש. נופל בחזרה להודעה ברורה בדפדפן שלא תומך ב-Web Speech API.
- **עריכת מפת-חנות ע"י המשתמש** — כפתור "✏️ ערוך מפה" במסך "מפת חנות"
  מאפשר להוסיף מחלקה חדשה לתא ריק, לשנות שם/אייקון למחלקה קיימת,
  להזיז אותה לתא אחר, למחוק אותה, ולהגדיל/להקטין את גודל-הרשת —
  הכל נשמר ב-`localStorage` (`src/lib/storeConfig.js`) ומשתקף **מיד**
  בכל מסך שמציג מחלקות (חיפוש-מוצר/עגלה/ניווט/AR/צ'קאין-מיקום), כי
  כולם קוראים מאותו "מקור-אמת" חיצוני-לרינדור
  (`useSyncExternalStore`, `src/lib/useStoreConfig.js`). מוגן מפני
  מחיקת מחלקה שיש בה מוצרים (חוסם עם הודעה — עריכת-הקטלוג עצמו היא
  פיצ'ר נפרד) ומפני מחיקת מחלקות "כניסה"/"קופות". כפתור "↺ אפס למצב
  ברירת-מחדל" מחזיר את המפה המקורית.
- **סריקת ברקוד** (`src/components/BarcodeScanner.jsx`) — כפתור "📷
  סרוק ברקוד" ברשימת-הקניות. כל מוצר בקטלוג מקבל ברקוד-דמה ייחודי
  (פורמט EAN-13, קידומת 729). כשהדפדפן תומך ב-`BarcodeDetector` הילידי
  (Chrome/Edge) הסריקה **אמיתית** — לולאת-זיהוי חיה על זרם-המצלמה; יש
  גם **שדה-הקלדה ידני** תמיד-זמין (גם ללא מצלמה/כשאין תמיכה בדפדפן) —
  חשוב גם לנגישות וגם כי אין ברקודים פיזיים אמיתיים להראות למצלמה
  בהדגמה. מוצר-שנמצא מציג שם/מחיר/מיקום + "הוסף לרשימה" ו"פרטים
  נוספים" (פותח את אותו `ProductDetail` הקיים — שימוש-חוזר, לא נבנה
  UI כפול).
- **חיפוש מוצר לפי תמונה** (`src/components/ImageProductSearch.jsx`) —
  כפתור "📸 חפש לפי תמונה". **זיהוי-דמה מוצהר בבירור** (אין מודל-ראייה
  אמיתי בהיקף הזה): צילום מהמצלמה נדגם לכמה בייטים ומשמש כ-seed
  דטרמיניסטי (`src/lib/imageRecognitionMock.js`, אותו `seededRandom`
  ששימש כבר להיסטוריית-מחירים) לבחירת 3 "מועמדים" מהקטלוג — בדיוק כמו
  שממשקי-AI אמיתיים מחזירים כמה candidates, רק שכאן זה שקוף-לגמרי
  שהוא mock. המשתמש בוחר את המוצר הנכון מהרשימה (או "אף אחד מאלה —
  חפש ידנית"). זרם-המצלמה מנוהל דרך hook משותף חדש
  (`src/lib/useCameraStream.js`) שגם `CameraNav`/AR רוענן להשתמש בו —
  אותה לוגיקת-מצלמה במקום אחד, לא שלוש גרסאות כפולות.
- **מוצרים חלופיים** — `getAlternatives` (`src/data/storeData.js`)
  מציעה עד 4 מוצרים מאותה `category` (נופלת לאותה מחלקה אם אין
  מספיק), מוצג בסעיף "🔁 מוצרים דומים" בתחתית `ProductDetail.jsx`
  (המסך הקיים — לא נבנה UI כפול). "➕ הוסף" זמין תמיד; "↔ החלף" (מחליף
  את המוצר המקורי בעגלה) מופיע **רק** כשנפתח מתוך העגלה (לחיצה על שורת
  מוצר ב-`ShoppingList`), לא מקטלוג-חיפוש כללי. כפתור "❌ לא נמצא"
  הקיים בניווט (`Navigation.jsx`) פותח עכשיו את אותו מסך-חלופות ישירות
  מזרימת-הקנייה.
- **מבצעים חכמים** — 8 מוצרים בקטלוג מסומנים עם `salePercent`
  (`getSalePrice`). רכיב משותף חדש `PriceTag.jsx` מציג מחיר-רגיל או
  מחיר-מבצע (מקורי-חצוי + מוזל + תג-אחוזים) בכל מקום שכבר מציג מחיר —
  חיפוש/עגלה/פרטי-מוצר/תוצאת-סריקה/מועמדי-תמונה. **התראת-קרבה**:
  כשמגיעים בניווט לתחנה שיש בה פריט-עגלה במבצע, מוצג באנר "🏷️ מבצע
  בתחנה זו!" (גם במסך הניווט הרגיל וגם ב-AR) — סה"כ-העגלה ממשיך לחשב
  לפי המחיר הרגיל (לא מגלם הנחות, כדי לשקף את מה שבאמת ישולם בקופה).
- **מצב משפחתי (מקומי)** — `src/lib/familyMembers.js` (אותו דפוס
  pub/sub כמו `storeConfig.js`). פאנל "👨‍👩‍👧 משפחה" ב-`ShoppingList`
  להוספת/הסרת בני-משפחה ובחירת "מי אני". כל פריט-עגלה מקבל בורר-שיוך
  (`assignItem` ב-`useShoppingList.js`); תג-השיוך מוצג בניווט הרגיל
  וב-AR. **כיתוב-קבוע:** "מקומי בלבד — לא מסונכרן בין מכשירים (דורש
  שרת, עדיין לא קיים)" — סנכרון-אמיתי בין טלפונים שונים דורש שרת
  ונשאר מחוץ להיקף; זו הסיבה שהפיצ'ר הזה נדחה בסבב הקודם ונבנה עכשיו
  רק בגרסתו המקומית.
- **חיזוי-קניות לפי הרגלים (מקומי)** — `src/lib/purchaseHistory.js`
  שומר תאריך בכל "סיום קנייה" בניווט (שגם מנקה את העגלה, כמו בקנייה
  אמיתית). למוצר שנרכש **פעמיים ומעלה** מחושב מרווח-רכישה ממוצע; אם
  עברו ~80% מהמרווח מאז הרכישה האחרונה, מוצג "💡 כנראה נגמר לך" עם
  צ'יפ-הוספה-מהירה ב-`ShoppingList`. מוצר-חדש לא מקבל תחזית — אין
  ניחוש-AI, רק חשבון על נתונים אמיתיים.
- **ניקוד ותגמולים (מקומי)** — `src/lib/points.js`. תג "🏆 X נק׳"
  בכותרת מצטבר על סריקת-ברקוד (+2), בחירה בחיפוש-תמונה (+2), עדכון-
  מיקום (+1), אימות-מוצר נמצא/לא-נמצא (+1), השלמת-קנייה (+10), עם 3
  דרגות (ברונזה/כסף/זהב). **כיתוב-קבוע:** "ניקוד מקומי להנאה — עדיין
  בלי מימוש-הטבות אמיתי (דורש שרת)".
- **מצב אופליין (PWA אמיתי)** — `vite-plugin-pwa` מייצר service-worker
  אמיתי שמקדם-שומר (precache) את קבצי-האפליקציה. אומת חי: לאחר טעינה
  ראשונה, ניתוק-רשת מלא ורענון-דף — האפליקציה עדיין נטענת במלואה
  מה-cache. זה **לא mock** — עובד גם ב-production build אמיתי
  (`npm run build && npm run preview`).

## מה לא בהיקף (במכוון)

עריכת קטלוג-המוצרים עצמו (שיוך מוצר למחלקה/מדף/אזור), זיהוי-תמונה AI
אמיתי, זיהוי-מדפים אמיתי במצלמה, מאגר מחירים ארצי אמיתי, וסנכרון
מצב-משפחתי/ניקוד בין מכשירים אמיתי — כל אלה דורשים שרת שעדיין לא
נבנה. יתווספו בסבבים הבאים לפי בקשה.

## הרצה

```bash
npm install
npm run dev      # שרת פיתוח
npm run build    # build לפרודקשן
npm run lint     # oxlint
npm run preview  # להריץ את ה-build לפרודקשן (נדרש כדי לבדוק מצב-אופליין בפועל — ה-service-worker לא פעיל תחת npm run dev)
```
