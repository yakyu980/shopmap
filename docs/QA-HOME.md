# דוח QA — דף הבית

## בדיקה חיה עם שני משתמשי QA — 2026-09-02

נבדקו התחברות, יצירת קבוצה, יצירת קישור הזמנה, הצטרפות משתמש שני ומעבר בין רשימה אישית לקבוצתית. יצירת הקבוצה וההצטרפות עברו, והמשתמש השני הופיע כחבר פעיל. מעבר חזרה לרשימה האישית עבד לאחר איפוס `activeGroupId` בעת החלפת משתמש.

## עדכון QA לאחר מימוש מצב קבוצה

נבדק מחדש לאחר `c1e3e3b` והשינויים שאחריו. בחירת קבוצה פותחת דף בית קבוצתי נפרד, עם רשימה ומועדפים נפרדים, פעולות רשימה, העברה אצווה, בחירת סניף קבוצתי ומונה טאבים לפי סכום הכמויות. הניווט מקבל את רשימת הקבוצה דרך adapter ב־`App.jsx`, ויציאה מחזירה למצב אישי. בדיקות build/lint/unit עברו.

עדיין נדרש אימות ידני עם Supabase פעיל: יש להריץ את שינויי הסכמה ב־`server/supabase-schema.sql`, להתחבר עם חשבון בדיקה, לבחור קבוצה ולבדוק הרשאת מצלמה. הסניף הקבוצתי ניתן לעריכה בדף הבית ונשמר בשרת, אך אין עדיין הצגת שם הסניף לאחר שמירה.

## סיכום מנהלים

דף הבית נטען לאחר התחברות ומכיל את פעולות הרשימה הבסיסיות. בחירת קבוצה מתוך הפרופיל מחליפה את הקונטקסט לדף בית של אותה קבוצה; חזרה למצב אישי מחזירה את הרשימה האישית. יש גם כפתור מצלמה מרכזי לסריקת ברקוד או לזיהוי מוצר בתמונה.

## בדיקה חיה שבוצעה

ב־localhost נפתח מסך ההתחברות ונצפו:

- כותרת SuperNav AI.
- כפתורי התחברות והרשמה.
- שדות שם משתמש וסיסמה.
- כפתור “שכחתי סיסמה”.

לא בוצעה התחברות בפועל כי אין חשבון בדיקה שסופק. לכן הזרימות שאחרי AuthGate מסומנות לפי ראיות קוד, ולא כבדיקה אינטראקטיבית מלאה.

## מצלמה וברקוד — הערכת סיכון

הקוד אכן מספק את הפיצ'ר שביקשת: כפתור יחיד בדף הבית פותח modal שמכוון את המצלמה למוצר או לברקוד. ברקוד מזוהה אוטומטית דרך `BarcodeDetector` כאשר הדפדפן תומך; אחרת יש צילום ברקוד ושדה ידני. זיהוי מוצר בתמונה נשלח ל־Gemini דרך השרת כאשר `GEMINI_API_KEY` מוגדר.

הבדיקה החיה לא אישרה צילום בפועל משום שאין הרשאת מצלמה שניתנה בסשן ואין חשבון מחובר. בנוסף, `getUserMedia` ו־`BarcodeDetector` דורשים secure context (HTTPS, כאשר localhost הוא חריג לפיתוח), ו־`BarcodeDetector` אינו נתמך בכל הדפדפנים. ראו [MDN BarcodeDetector](https://developer.mozilla.org/en-US/docs/Web/API/BarcodeDetector) ו־[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

## תקלות/פערים לפי עדיפות

### P1 — דף בית קבוצתי עדיין בסיסי

קיים `activeGroupId` ו־provider שמזין את `Home` ברשימת הקבוצה. עדיין אין WebSocket, היסטוריית פעילות או UX מלא בסגנון WhatsApp; כרגע הסנכרון הוא polling כל 5 שניות.

### P1 — הגבלת כמות עדיין חסרה

השרת אוכף הגבלת קטגוריה ומוצר בהוספה ובהעברה, אך אין עדיין שדה או כלל להגבלת מספר יחידות.

### P2 — UX של transfer אישי → קבוצה בסיסי

קיימת העברה אצווה עם רשימת דחויים, אך אין עדיין מסך אישור מפורט או בחירה פריט־פריט.

### P2 — כשלי API לא נראים מספיק בדף הבית

במצב קבוצה מוצג banner שגיאה לטעינת הקבוצה; עדיין אין feedback מפורט לכל פעולת הוספה/סימון/הסרה שנכשלה. העברה אצווה מחזירה דחויים, אך אין מסך אישור פריט־פריט.

### P2 — כיסוי QA אוטומטי חסר

קיים רק `src/lib/chainPriceBlocks.test.js`. אין Playwright/Cypress או בדיקות React לדף הבית, ולכן אין כרגע regression אוטומטי לזרימות login → profile → group → list → camera.

## מסקנה

דף הבית כולל כעת מצב אישי ומצב קבוצה בסיסי, עם רשימות ומועדפים נפרדים, סנכרון polling, העברה אצווה ואכיפת הרשאות קטגוריה/מוצר. עדיין חסרים הגבלת כמות, WebSocket, בחירה פריט־פריט ב־transfer ובדיקת מצלמה ידנית עם חשבון בדיקה והרשאת מצלמה.
